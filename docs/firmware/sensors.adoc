== Überblick

Die BeeLight-Firmware implementiert drei Sensor-Module, die jeweils als eigenständige Initialisierungsmodule mit Zephyr SYS_INIT registriert sind.
Jedes Modul abonniert einen periodischen ZBus-Kanal und veröffentlicht seine Messdaten auf einem dedizierten Datenkanal.

[cols="3,2,2,4", options="header"]
|===
| Modul | Sensor | Messintervall | Zigbee-Cluster
| `src/sensors/light.c`       | APDS-9306 | 5 Minuten   | Illuminance Measurement
| `src/sensors/environment.c` | BME688    | 5 Minuten   | Temperature, Pressure, Humidity (+ CO₂/VOC/IAQ optional)
| `src/sensors/battery.c`     | VBATT ADC | 24 Stunden  | Power Configuration
|===

== Lichtsensor – APDS-9306

=== Hardware

Der Broadcom APDS-9306 ist ein digitaler Umgebungslichtsensor (ALS) mit I²C-Schnittstelle.
Er misst die Beleuchtungsstärke in Lux und wird im Devicetree unter dem Label `apds9306` referenziert.

NOTE: Der APDS-9306-Treiber wird über Zephyr-Patches aus `patches/zephyr/` in den Build eingebunden.

=== Funktionsweise

Das Modul abonniert `periodic_5min_chan` und führt bei jedem Tick eine Messung durch:

[source,c]
----
sensor_sample_fetch(apds9306);
sensor_channel_get(apds9306, SENSOR_CHAN_LIGHT, &sensor_val);
evt.light = sensor_val.val1;
zbus_chan_pub(&light_data_chan, &evt, K_NO_WAIT);
----

Die rohe Sensorausgabe (Lux) wird in `main.c` in den logarithmischen Zigbee-Illuminance-Wert umgerechnet:

[source,c]
----
zb_uint16_t measured = (evt->light == 0)
    ? 0
    : (zb_uint16_t)(10000 * log10((double)evt->light) + 1);
----

=== Debug-Modus

Bei aktiviertem `CONFIG_DEBUG` und nicht vorhandenem Sensor werden synthetische Testdaten
(inkrementierender Zähler) auf `light_data_chan` veröffentlicht.

=== Konfiguration

[cols="2,4", options="header"]
|===
| Kconfig-Option | Beschreibung
| `CONFIG_APDS9306` | Aktiviert den APDS-9306-Treiber (wird über Zephyr-Patch bereitgestellt)
|===

== Umgebungssensor – BME688

=== Hardware

Der Bosch BME688 ist ein integrierter Gas-Sensor mit I²C-Schnittstelle, der Temperatur, Luftdruck,
relative Luftfeuchtigkeit sowie Gaswiderstände (für VOC/IAQ/CO₂-Äquivalent) misst.
Im Devicetree wird der Sensor unter dem Label `bme688` referenziert.

=== Betriebsmodi

==== Basismode (ohne BSEC2)

Es werden Temperatur, Luftdruck und Luftfeuchtigkeit gemessen:

[cols="2,3", options="header"]
|===
| Zephyr-Kanal | Messgröße
| `SENSOR_CHAN_AMBIENT_TEMP` | Temperatur in °C
| `SENSOR_CHAN_PRESS`        | Luftdruck in Pa
| `SENSOR_CHAN_HUMIDITY`     | Relative Luftfeuchtigkeit in %
|===

==== IAQ-Modus (mit BSEC2)

Bei aktiviertem `CONFIG_BME68X_IAQ` werden zusätzlich folgende Kanäle ausgewertet:

[cols="2,3", options="header"]
|===
| Zephyr-Kanal | Messgröße
| `SENSOR_CHAN_CO2`  | CO₂-Äquivalent in ppm
| `SENSOR_CHAN_VOC`  | VOC in ppm-Äquivalent
| `SENSOR_CHAN_IAQ`  | IAQ-Index (0–500)
|===

Jeder BSEC2-Wert beinhaltet zusätzlich einen `tolerance`-Wert, der die Messgenauigkeit/-verlässlichkeit angibt.

=== Messablauf

[source,c]
----
sensor_sample_fetch(bme688);
sensor_channel_get(bme688, SENSOR_CHAN_AMBIENT_TEMP, &sensor_val);
evt.temperature = sensor_val.val1;
// ... weitere Kanäle
zbus_chan_pub(&env_data_chan, &evt, K_NO_WAIT);
----

=== Konfiguration

[cols="2,4", options="header"]
|===
| Kconfig-Option | Beschreibung
| `CONFIG_BME68X_IAQ` | Aktiviert BSEC2-Integration für CO₂, VOC und IAQ-Messung
|===

== Batterieüberwachung – VBATT

=== Hardware

Die Batteriespannung wird über einen ADC-Spannungsteiler gemessen.
Das Zephyr-Gerät ist im Devicetree unter dem Label `vbatt` als `voltage-divider`-Sensor definiert.

=== Messkette

Die Messung erfolgt alle 24 Stunden:

[source,c]
----
pm_device_runtime_get(vbatt);
sensor_sample_fetch(vbatt);
sensor_channel_get(vbatt, SENSOR_CHAN_VOLTAGE, &sensor_val);
evt.voltage = (sensor_val.val1 * 1000) + (sensor_val.val2 / 1000);  /* in mV */
pm_device_runtime_put(vbatt);
----

=== Ladestandsberechnung

Der prozentuale Ladestand wird linear zwischen den konfigurierten Grenzspannungen interpoliert:

[source,c]
----
#define BEELIGHT_RATED_VOLTAGE_MV   3300UL   /* 100 % */
#define BEELIGHT_EMPTY_VOLTAGE_MV   2700UL   /*   0 % */
----

[source,c]
----
int32_t remaining = (evt->voltage - BEELIGHT_EMPTY_VOLTAGE_MV);
remaining = (remaining * 100) / (BEELIGHT_RATED_VOLTAGE_MV - BEELIGHT_EMPTY_VOLTAGE_MV);
dev_ctx.power_attr.percent_remaining = remaining * 2;  /* Zigbee: 200 = 100 % */
----

NOTE: Im Zigbee Power Configuration Cluster repräsentiert ein `BatteryPercentageRemaining`-Wert von 200 den vollen Ladezustand (100 %).

=== Voltage-to-ZCL-Umrechnung

Die Batteriespannung wird für das Zigbee-Cluster durch ganzzahlige Division durch 100 auf die ZCL-Einheit (100 mV pro Einheit) skaliert:

[source,c]
----
dev_ctx.power_attr.voltage = evt->voltage / 100;
----
